# 0001: Adopt Clan for machine lifecycle, keep den for composition

Status: **Accepted** (2026-11-18, user decision; bead nch-sny.7).
Evidence: [`docs/plan.md#spike-findings`](../plan.md#spike-findings), from a
disposable VM (`clan-spike`, pve-rog VM 100).

## Decision

Run the homelab from this repo with clan-core owning install, hardware
reports, secrets (vars), SSH host certificates and routine deploys, and den
owning host, user and Home Manager composition. Routers deploy with
deploy-rs.

## What the spike showed

| Question | Result |
| --- | --- |
| den modules as clan machines | Works. den hosts set `intoAttr = [ ]`; clan imports `mainModule`. Users, groups, Home Manager verified on a running machine. |
| Install flow | One `clan machines install` with nixos-facter replaces `just gen-identity` / `rekey` / `install` and hand-written hardware config. |
| Secrets | Vars generate, encrypt (admins + that machine only) and deploy. Operator SSH keys are the admin identity; no age key file. Adding a machine touches nothing else's secrets. |
| agenix during migration | Coexists, using the clan-managed host key, after one ordering fix (otherwise it failed silently on first boot). |
| SSH host trust | CA-signed certificates: strict checking with no stored host keys; keys survive reinstall. Replaces `ssh-keys/*-host-*` and the known_hosts generator. |
| Deploy safety | `clan machines update` has no rollback: a lockout survives reboot. deploy-rs rolls back automatically on clan-built systems. |
| darwin, standalone homes | macOS machines evaluate through clan (`machineClass = "darwin"`); Proxmox root homes stay den-only. |

## What we keep from den

Aspects, users, Home Manager, the dendritic layout. Nothing found in the
spike required giving any of it up.

## Costs and risks

- Every agenix secret moves to vars eventually (one domain at a time; both
  work side by side meanwhile).
- unified's aspects are a local den-inspired framework, so porting means
  rewriting them as `den.aspects.*`.
- Clan commits on its own (facter, inventory, vars); review before pushing.
- Two deploy tools: deploy-rs for routers and risky changes, clan elsewhere.
  deploy-rs needs one good deploy after install before it can roll back.
- Clan is younger than agenix/nixos-rebuild; pin its release branch (26.05).
- Certificates are issued without expiry; revocation would be manual.

## If no-go

Stay on unified and adopt separately: agenix-rekey or nixos-artifacts,
nixos-facter, deploy-rs, an SSH CA key as a secret, one inventory
([`docs/plan.md#fallback`](../plan.md#fallback)).
